# StockFlow — заказы и обращения клиентов

[![Verify](https://github.com/Regilios/task-management-app/actions/workflows/verify.yml/badge.svg?branch=main)](https://github.com/Regilios/task-management-app/actions/workflows/verify.yml)

Портфолио-проект backend на Java: оформление заказов, история сообщений клиента, очередь обращений и работа оператора. Текущий срез содержит доменные модели и сервисы с хранением в памяти, а также Spring Boot-оболочку с PostgreSQL, Liquibase и проверкой готовности.

Первый этап завершён 2026-10-23: доменные сценарии заказов и обращений работают в памяти. Реализация бизнес-сценариев находится в `core`; инфраструктура запуска — в `app`. Следующий этап, HTTP API на Spring, начат в `02-stage`.

## Возможности текущего среза

- Черновик заказа с позициями: добавление, удаление, изменение количества и суммирование повторного кода товара.
- Подтверждение непустого заказа и отмена черновика с определёнными правилами повторных и запрещённых переходов.
- Создание и поиск заказов клиента с сохранением порядка и защитой состава возвращаемых списков.
- История сообщений: стабильный порядок добавления, успешный повтор одинаковых данных и отказ при конфликтующем идентификаторе.
- Диалоги с последовательными обращениями, назначение ответственного оператора, закрытие и общая очередь ожидающих обращений.
- Поиск текущих открытых обращений за включительный период времени открытия с определённым порядком результатов.
- Создание заказа из обращения и привязка существующего заказа того же клиента. Заказ имеет не больше одного исходного обращения; одно обращение может быть источником нескольких заказов.

Контракты завершённого среза: [этап 01](docs/stages/01-stage.md). Направление текущей разработки и её границы: [этап 02](docs/stages/02-stage.md).

## Стек

| Часть | Технологии |
| --- | --- |
| Язык и сборка | Java 21, Maven Wrapper 3.9.16, многомодульный Maven |
| Приложение | Spring Boot 4.0.8, Actuator, Spring Data JPA и JDBC-драйвер PostgreSQL |
| Инфраструктура БД | PostgreSQL 16, Liquibase, Hibernate `ddl-auto: validate` |
| Тестирование | JUnit Jupiter, AssertJ, Testcontainers |
| Локальный запуск и CI | Docker Compose, GitHub Actions |

PostgreSQL пока используется для технического маркера и инфраструктурных проверок. Доменные объекты ещё не сохраняются в БД; бизнесовый HTTP API отсутствует.

## Быстрая проверка

Нужен JDK 21. Системный Maven не требуется: Wrapper скачивает закреплённую версию и проверяет SHA-256.

Windows PowerShell:

```powershell
.\mvnw.cmd -B -ntp -pl core test
```

Linux/macOS:

```bash
chmod +x mvnw
./mvnw -B -ntp -pl core test
```

Эти команды компилируют `core` и запускают его тесты без Spring-контекста и Docker. Локальная проверка от 2026-10-23: 135 выполнений, 0 failures/errors/skipped. Набор включает восемь сценариев связи заказов с обращениями и семь сценариев выборки открытых обращений за период.

Полная сборка и инфраструктурные тесты требуют работающего Docker:

```powershell
.\mvnw.cmd -B -ntp -Pintegration verify
```

GitHub Actions настроен на выполнение этой команды на push и pull request. Результат конкретного запуска доступен в [Actions](https://github.com/Regilios/task-management-app/actions/workflows/verify.yml). Проверка `core` без Docker и полный интеграционный запуск подтверждают разные части системы.

На 2026-10-23 локальный Docker Engine недоступен; интеграционный `verify` при завершении первого этапа локально не запускался.

## Запуск приложения

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 up
```

После запуска: [readiness](http://127.0.0.1:18080/actuator/health/readiness). По адресу `/` пока нет пользовательского интерфейса или бизнесовых маршрутов.

Требования, команды Compose, конфигурация и диагностика: [SETUP.md](docs/SETUP.md).

## Структура

| Каталог | Назначение |
| --- | --- |
| `core/src/main/java/dev/stockflow/core/model` | Заказы, позиции, сообщения, диалоги и обращения |
| `core/src/main/java/dev/stockflow/core/service` | Хранение в памяти, поиск и координация операций |
| `core/src/test` | Тесты моделей и сервисов |
| `app` | Spring Boot, конфигурация БД, миграции и инфраструктурный тест |

## Ветки и этапы

| Ветка | Назначение | Документация |
| --- | --- | --- |
| `main` | Актуальный завершённый срез; обновляется по завершении этапов | Этот README |
| `01-stage` | Замороженный результат первого этапа: модель заказов и обращений | [01-stage](docs/stages/01-stage.md) |
| `02-stage` | Рабочая ветка следующего этапа: HTTP и Spring | [02-stage](docs/stages/02-stage.md) |

Итог первого этапа сохранён в `01-stage` и перенесён в `main`. Разработка продолжается в `02-stage` от этого завершённого среза. Для каждого начатого этапа создаётся отдельное описание в `docs/stages`; после завершения его результат переносится в `main`, а ветка этапа сохраняет итоговый срез.

## Ограничения

Бизнес-данные живут в памяти процесса и теряются при перезапуске. Согласованность конкурентных команд, авторизация, бизнесовые REST-контроллеры, складские остатки и резервирование пока не реализованы. Это учебный портфолио-проект; описание относится к текущему коду и проверкам.
