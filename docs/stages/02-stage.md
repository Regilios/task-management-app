# 02-stage — HTTP и Spring

Этап начат 2026-10-23. Рабочая ветка `02-stage` создана от завершённого первого этапа; `main` содержит последний завершённый срез, а `01-stage` сохраняет результат доменной модели.

## Исходное состояние

Модуль `core` содержит заказы, диалоги, обращения и сервисы с хранением в памяти. Их контракты описаны в [этапе 01](01-stage.md).

Модуль `app` содержит Spring Boot-оболочку, конфигурацию PostgreSQL и Liquibase, Actuator readiness и инфраструктурный тест. PostgreSQL пока используется только для технического маркера; доменные данные не сохраняются в БД. Бизнесовый HTTP API ещё не реализован.

## Направление разработки

- Создание и чтение заказа через REST с определёнными входными данными, ответами и HTTP-статусами.
- Единое представление ошибок некорректного запроса, неизвестного заказа и бизнес-конфликта.
- Чтение списка заказов с фильтрацией, ограничением размера страницы и определённым порядком.

Это план этапа. Контроллеры, DTO, бизнесовые маршруты и HTTP-тесты этих операций пока отсутствуют. Конкретные контракты будут добавлены вместе с реализацией.

## Проверки

Существующие проверки доменной модели запускаются без Docker:

```powershell
.\mvnw.cmd -B -ntp -pl core test
```

Полная сборка и инфраструктурные тесты требуют работающего Docker:

```powershell
.\mvnw.cmd -B -ntp -Pintegration verify
```

Эти команды описывают способ проверки исходного среза. Они пока не подтверждают наличие бизнесового HTTP API. Команды запуска приложения и требования окружения приведены в [SETUP.md](../SETUP.md).
